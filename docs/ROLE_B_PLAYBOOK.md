✅ = done in this skeleton · 🔲 = yours to do

## STEP 0 (hour 0, before anyone else writes code): push the skeleton
You push first, so every shared file exists exactly once before anyone branches. That's what
prevents "both added README.md / pyproject.toml / __init__.py" conflicts.

```bash
# if the team repo is EMPTY (or only has PRD.md):
cd reigns
git init -b main          # skip if you cloned the team repo
cp /path/to/PRD.md .      # PRD must sit at the repo root
git add -A && git commit -m "FR-B2: repo skeleton, §12 schemas v1, fixtures, engine core"
git remote add origin <team repo url>    # skip if cloned
git push -u origin main
```
If the repo already has a README or other files, pull first, copy this skeleton in, keep
whichever README you prefer, and commit once.

Then in team chat: **"Skeleton is on main. Everyone clone now, run
`git config reigns.role <X>` + `sh scripts/install_hooks.sh`, and branch from main."**

On GitHub: Settings → Branches → protect `main` (require PR, require Code Owner review), and
replace `@role-a` … `@role-d` in `.github/CODEOWNERS` with real usernames.
